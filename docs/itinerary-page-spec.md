# 行程詳細頁規格 v1

確認日期：2026-10-22（Asia/Taipei）。

狀態：使用者已確認此規劃，作為後續共用模板與元件的實作依據。本文件不表示頁面已完成實作。

## 目標

以手機旅途中查看為主要情境。總覽掌握整趟旅程，每日行程處理當天移動。必要資訊直接顯示，補充資訊展開查看。日本、韓國與未來新增旅程使用相同版型與顯示規則。

## 頁面結構

頁首只保留返回國家清單、旅程名稱、起訖日期。主要入口固定為「總覽」「每日行程」。不在頁首重複堆疊大型摘要卡；其他旅程由國家清單進入。

### 總覽

依序顯示以下四區：

| 區塊 | 直接顯示 | 展開查看 |
| --- | --- | --- |
| 機票 | 去回程、航空公司、航班、日期、時間、機場、航廈 | 行李、座位、備註 |
| 住宿 | 飯店名稱、入住與退房日期、地址、導航 | 入住與退房時間、房型、訂單資料 |
| 每日摘要 | 日期、主要地區、當日重點 | 點擊進入當天行程 |
| 注意事項 | 未完成安排、重要預約、期限 | 一般提醒、補充文件 |

注意事項依重要性排列。影響當天行程的時間或條件，即使原本屬於詳細資料，也必須提升至直接可見的位置。

### 每日行程

由上至下：

1. 前一天、日期選擇器、後一天。
2. 當日地區與行程重點。
3. 今晚住宿與導航；有住宿資料才顯示，不推定未提供即無住宿。
4. 依活動順序排列的時間軸，活動之間插入交通資訊。
5. 當日地圖入口。

日期可直接選擇，不依賴長列橫滑日期頁籤。切換日期的控制保持可用，返回某天保留閱讀位置。具體預設日期與狀態保存方式在實作時定義，不據此假設任何當下活動。

## 共用活動卡

固定資訊順序：

1. 時間、活動類型。
2. 地點名稱，長名稱允許換行。
3. 必要提醒，例如預約時間、提前報到、最後入場與當天休息。
4. 「導航」「詳細資料」操作。
5. 詳細資料：當地名稱、完整地址、推薦品項、費用、一般備註。

未安排時間顯示「時間待安排」。必要提醒不可藏在收合內容內。餐廳主選保留於時間軸，備選以「備選 N 間」收合，展開後沿用相同資料欄位與卡片規則，不當成額外必去行程。

## 交通

交通資訊置於相鄰活動之間，對應上一站到下一站。

- 預設顯示交通方式、預估總時間。
- 展開顯示路線、搭乘方向、上下車站、轉乘、出口。
- 已知有行李或無障礙需求時，重要出口提醒直接可見。
- 區分預估與即時資訊，不把靜態資料標示為即時導航。
- 旅程設定主要地圖服務，活動卡提供一個主要導航入口；其他地圖服務置於詳細資料。

## 機票元件

每個航段使用同一元件，固定順序為：

1. 去程／回程或航段標籤、航空公司、航班、日期。
2. 出發與抵達時間。
3. 機場代碼、機場名稱、航廈。
4. 飛行時間。
5. 可展開的行李、座位與備註。

所有時間採各機場當地時間，跨日抵達需標示。星期、飛行時間與跨日資訊由含時區的時間資料推算。轉機由多個航段組成，不壓成一組起降時間。

桌面去回程可並排，手機上下排列。總覽與每日行程引用同一筆航段資料與同一個元件。出發日顯示對應去程，回程日顯示對應回程。

### 訂位代碼政策（2026-10-22）

網站維持方便查看行程的靜態架構。公開航班資料與 HTML 不包含機票訂位代碼，不為此需求增加密碼解鎖或登入後端。訂位管理回到航空公司 App 或確認信處理。

本次移除兩趟日本行程的訂位代碼，包括總覽與每日航班卡片中的重複內容。本次未移除韓國既有飯店訂單資訊，也未重寫 Git 歷史。刪除目前版本中的代碼，不會清除歷史提交或先前下載的副本。

## 住宿元件

總覽與當日引用同一筆住宿資料。每日摘要顯示當晚住宿與導航；換飯店當天另外顯示退房、入住資訊。必要報到或退房時限直接可見，不只放在詳細資料。

## 資料狀態

不得由缺值推定業務狀態：

| 狀態 | 顯示 |
| --- | --- |
| 明確尚未安排航班 | 去程／回程待安排 |
| 已選航班但未訂票 | 未訂票 |
| 未提供航廈 | 航廈待確認 |
| 未提供行李額度 | 行李額度待確認 |
| 明確尚未劃位 | 尚未劃位 |
| 未提供座位資訊 | 座位資料未提供 |
| 其他未確認欄位 | 依欄位標示待確認或資料未提供 |

## 視覺、操作與地圖

- 延續深色風格，統一卡片圓角、字級、間距、按鈕與狀態標籤。
- 正文以 16px 為基準，時間、名稱、提醒有清楚層級。
- 顏色搭配文字標籤，不以顏色作為唯一辨識方式。
- 手機單欄，桌面可將當日地圖放在時間軸旁。
- 地圖按需載入；失敗時仍能閱讀活動、使用導航連結。
- 編輯模式另行進入，查看模式保持精簡。本規格未定義完整編輯流程。
- 共用樣式與元件統一管理，旅程不得自行複製或覆寫機票卡片版型。

## 資料與元件原則

每筆航段、住宿與活動只有一份資料來源；總覽、每日行程、摘要與地圖從該資料產生，避免各自維護內容。國家或城市差異以資料與選用區塊處理。

本文件定義顯示與互動行為；完整 schema、儲存、登入、同步及分享權限需另外設計，不視為已實作或已確定的技術選型。

## 驗收條件

1. 不展開內容即可理解當天活動順序、時間、主要移動方式與住宿；未知資訊有明確狀態。
2. 有可用位置資料的活動可直接導航；缺少位置資料時提供明確說明，不顯示失效操作。
3. 航廈、預約與入住等關鍵資訊不因收合而難以取得；影響當天行動的提醒直接可見。
4. 相同資料在不同國家旅程、相同視窗尺寸下，呈現相同元件與版型。
5. 修改同一筆航班、住宿或活動資料時，所有引用位置同步更新。
6. 手機、桌面、長地點名稱、缺值、多段航班、跨日抵達、換飯店、地圖載入失敗皆需驗證。
7. 日本行程的公開檔案不可包含機票訂位代碼，須同時檢查總覽與每日卡片的重複內容。
